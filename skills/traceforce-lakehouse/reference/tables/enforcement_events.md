# enforcement_events

One row per thing TraceForce's hook enforced on a prompt or tool call (block/warn), recorded authoritatively at the decision. Append-only audit ledger, NOT a finding and NOT an incident; it never feeds the incidents pipeline. Use it for enforcement effectiveness ('what did we prevent'), not detection counts. A blocked prompt never produces a sensitive_data_findings row; this is where it is recorded.

Joins:
- person/session (identity enrichment, may be unresolved): the ledger is identity-less, so LEFT JOIN agent_conversations on (org_id, device_id, conversation_external_id) — but resolve identity ONLY when exactly one row matches. The same conversation_external_id can exist under two agent_account_id on a device (agent_conversations is unique on (org_id, agent_account_id, conversation_external_id)), so match via a scalar/aggregated subquery (or a GROUP BY that keeps one enforcement row) to avoid fanning out and double-counting enforcement, and leave the person NULL when >1 candidate matches or the conversation row is absent. Then agent_conversations.agent_account_id → agent_accounts.agent_email
- device owner (for display): device_id → devices.device_native_id → device_owner_mappings.owner_email
- agent name: agent_type → agent_catalog.agent_type (the ledger's agent_type is the AgentIdentity decoded to text, same vocabulary as agent_catalog.agent_type)
- the enforced tool call: tool_use_id = agent_events.tool_call_id (same session) on tool-call surfaces; for prompt surfaces the turn is message_external_id (see its note)

Unique in the source (Iceberg does not enforce it; the mirror is keyed by `id`):
- (org_id, record_id): the ledger's dedup key (a redelivered upload no-ops), NOT one prevention per action. Scout mints a fresh record_id in every PROCESS, so a double-registered hook (an exec-form and a shell-form copy of one PreToolUse fire for the same command) emits TWO deny/ask rows for ONE action. Count prevention by distinct (org_id, conversation_external_id, tool_use_id, control, surface, action) when tool_use_id is present (the Prevented view / UI blockIdentity dedup key), never by raw record_id row
- (org_id, correlation_id) WHERE action = 'allowed_after_warn': one override per warning episode; a fresh warning after the deny-once marker expires gets a new correlation_id and its own override row

| column | type | meaning |
|---|---|---|
| `id` | string | Primary key (uuid as text). |
| `org_id` | string | Your TraceForce org id. Constant within this lakehouse. |
| `device_id` | string | → devices.id |
| `sandbox_id` | string | → sandboxes.id; NULL when the row is about the host device itself. |
| `conversation_external_id` | string | The agent's own session id the hook stamped; equals agent_events.session_id and agent_conversations.conversation_external_id. Stored as text, NOT a foreign key: the ledger records the attempt whether or not the conversation row exists yet. |
| `record_id` | string | The hook's per-enforcement id; the ledger's dedup key (unique per (org_id, record_id)). A redelivered upload no-ops. |
| `agent_type` | string | Which agent product the enforcement was for (decoded AgentIdentity text, e.g. 'claude_code'). |
| `control` | string | Which control decided, as text: 'containment' / 'sensitive_data' / 'mcp_access' / 'mcp_tool_permission'. |
| `surface` | string | What it applied to, as text: 'tool_call' / 'file_read' / 'prompt' / 'prompt_file'. |
| `mode` | string | The policy mode, as text: 'block' or 'warn'. An allowed_after_warn override is also mode = 'warn', so counting warnings by mode double-counts an overridden warning (its deny_once plus the override); count warnings as action IN ('ask', 'deny_once') instead. |
| `action` | string | What actually happened, as text: 'deny' (block: denied), 'ask' (warn: the agent's own approval dialog asked the user — NOT a prevention on its own), 'deny_once' (warn: withheld until the user re-submitted), 'allowed_after_warn' (warn: re-submitted, so let through). For Prevented, count 'deny' and a 'deny_once' with no matching 'allowed_after_warn' on its (org_id, correlation_id) (the user overrode it — see correlation_id), and EXCLUDE 'allowed_after_warn'. An 'ask' is resolved from agent_events on the same tool_call_id: Claude-family on the tool_decision (accept = overridden; a reject is prevented UNLESS its source = 'hook', which is a user-installed hook denying what TraceForce only asked about — not TraceForce's own prevention); Copilot on its execute_tool span (a clean span = overridden; error_type 'denied'/'cancelled' = prevented — its permission span carries no call id, so key on the execute_tool span, not that). Unknown only until such a row joins (e.g. activity newer than the last export); counting every 'ask' as prevented over-counts, because an approved ask writes no allowed_after_warn row. |
| `tool_name` | string | The tool the call used (e.g. 'Bash'); '' for a prompt enforcement. An MCP call names its server too, as 'MCP:<server>/<tool>' when the server is known and the agent's raw tool name otherwise, so the spelling varies (SELECT DISTINCT tool_name). Any control can deny an MCP call (containment and sensitive_data too, not only mcp_access / mcp_tool_permission). |
| `tool_use_id` | string | The agent's tool-call id for a tool enforcement; equals agent_events.tool_call_id. NULL for prompt enforcements and for hook callbacks that carry no per-call id — Cursor's generic preToolUse (and its shell callback on cursor-agent >= 2026.10.01) DO carry one, but its file-read and MCP-execution callbacks do not; those rows cannot be matched to agent_events on tool_use_id. |
| `message_external_id` | string | The agent's prompt/turn id (Claude prompt id, Codex turn id, Cursor generation id) — present on TOOL-CALL rows too (they carry the turn's id), not only prompts. NULL only for agents that emit no prompt/turn id (Copilot). |
| `correlation_id` | string | Session-salted per-warning-episode key on the WARN-PATH records only — a deny_once and the allowed_after_warn that overrode it; deny and ask carry NONE (NOT content-based — not guessable or linkable across sessions/orgs). Identical on a deny_once and its allowed_after_warn, so Prevented counts a deny_once ONLY when no allowed_after_warn shares its (org_id, correlation_id). Same-turn retries emit extra deny_once rows with the SAME key, so count a deny_once EPISODE by its distinct non-NULL (org_id, correlation_id), PLUS one per NULL-correlation_id deny_once row counted by record_id — those carry no key and never pair, so distinct-counting would collapse unrelated NULL-key attempts into one. deny and ask carry none and count by row. Both single-op and file warns RENEW it when the deny-once marker expires — a single-op warn keys on the episode's marker generation, a file warn on THAT file's own marker generation (per file, rotating per TTL). NULL on deny/ask and when there is no session or hashable operation. |
| `risky_action_subcategory` | string | The containment risky-action subcategory, as text (same vocabulary as connector_containment_findings.risky_action_subcategory); 'unknown' on sensitive-data rows. |
| `sensitive_data_category` | string | The sensitive-data category, as text (same vocabulary as sensitive_data_findings.category, e.g. 'credentials'); 'unknown' on containment rows. Only the DOMINANT category is stored (credentials, then identity/financial PII, then contact PII), so a prompt or file carrying several keeps the lowest-numbered one — a prompt with an AWS key and an SSN is stored as 'credentials' only, and a filter on this column misses the others; description names every type. |
| `rule_id` | string | The detector/rule that fired (sensitive-data only, e.g. a gitleaks rule id or a custom-regex rule id); NULL for containment, which has no discrete rule. |
| `description` | string | The sanitized, user-facing reason shown at the block/warn: it starts with the [Traceforce - Blocked] / [Traceforce - Action Required] tag and names the data types or the risky action. The quoted command and absolute home-dir paths are stripped and no secret value is included. NULL on an 'allowed_after_warn' override (nothing was prevented). |
| `detected_at` | timestamp | When the hook enforced the attempt (UTC); bound periods on this, not created_at. |
| `customer_storage` | string | JSON text: a pointer into the customer's BYO storage bucket; provider is 'gcs', 's3' or 'azure_blob'. On conversations it locates the session's uploaded activity objects; on findings it locates the evidence object holding the verbatim matched value / tool input; on enforcement_events it locates the verbatim blocked prompt / tool input. NULL when BYO storage is unconfigured or the source object is empty. Evidence is not in the lake by design; see reference/redaction.md. |
| `created_at` | timestamp | Row created (UTC). |
